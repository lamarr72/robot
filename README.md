## Введенные исправления
### Перевод проекта на систему сборки Apache Maven
- В корне проекта создан `pom.xml`, в котором определены координаты проекта (`groupID`, `artifactID`, `version`) и параметры компиляции.
- **Принцип работы:** Проект приведен к стандартной структуре maven: исходный код перенесен в `scr/main/java`.
  Для сборки используется `mvn clean pakage`. Настроен `.gitignore`.
### Рефакторинг и исправление ошибок
#### Рефакторинг меню в `MainApplicationFrame.java`
**Проблема:** Метод `generateMenuBar` был перегружен, что затрудняло его читаемость и дальнейшую модификацию.
**Решение:** применял принцип *декомпозиции*.
- Создание каждого меню вынесено в отдельные приватные методы: `createLookAndFeelMenu()`, `createTestMenu()`, `createExitMenu()`.
- Создан универсальный метод `createMenuItem()`. Он принимает текст, горячую клавишу и действие в виде `Runnable`. Это позволяет заменить громоздкие анонимные классы на компактные лямбда-выражения.
#### Оптимизация и многопоточность в `LogWindowSource.java`
**Проблема 1**: Утечка памяти. Сообщения добавлялись в список бесконечно.
**Проблема 2**: Потокобезопасность. При одновременной записи логов из разных потоков и обновлении окна интерфейса могло возникнуть исключение или искажение данных. 
**Решение**: ограничение очереди. Введен параметр `m_iQueueLength`. В методе `append` добавлена проверка на: если размер превышен, удаляется самое старое сообщение через `remove(0)`.
- Синхронизация: список сообщений обернут в `Collections.synchronizedList`, а чтение/запись защищены блоками `syncrinized`. 
- Слушатели: для списка слушателей использовал `CopyOnWriteArrayList`. Позволяет оповещать окна о новых логах, даже если в этот момент другое окно подписывается или отписывается от обновлений. 
  `CopyOnWriteArrayList` - позволяет другим потокам безопасно читать старую версию данных во время записи без блокировок. 
### Баг убегания робота за границы
**Проблема**: робот вычислял свои координаты на бесконечной плоскости, из-за чего уходил за пределы видимости. 
**Решение:** Внедрил класс логики зажимания координат. Метод `moveRobot`.
После вычисления новых координат `newX`, `newY` добавил проверки относительно текущих размеров окна: `getWidth()` и `getHeight`. Координаты принудительно ограничиваются, если `newX` присваивается 0. Или есть больше ширины окна - присваивается максимальное значение ширины. Аналогично для оси `Y`.
